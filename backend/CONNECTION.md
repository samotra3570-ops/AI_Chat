# 재사용 서버 연결 코드

단일 소유자의 앱 재설치·다른 기기 복구용 코드를 지원한다. 운영 서버 주소는 `https://acm-gateway-production.up.railway.app`이다. 기존 앱의 **AI / API → 일회용 연결 코드** 입력칸에도 재사용 코드를 넣을 수 있다. 앱 업데이트나 데이터 삭제 없이 기존 `POST /v1/pair`를 사용한다. 입력칸의 이름은 다음 앱 UI 변경 때 정리한다.

새 코드 원문은 `acm_connect_`에 암호학적으로 생성한 32바이트 URL-safe 문자열을 붙인 값이다. 예시·고정 코드·짧은 PIN으로 바꾸지 않는다. 코드는 운영자만 발급하여 비공개 파일로 보관하고 저장소·공개 인수인계·로그에 넣지 않는다. 서버에는 SHA256을 `ACM_CONNECTION_CODE_SHA256`으로 설정한다. 원문이나 API 키를 이 변수에 넣지 않는다.

서버 시작 시 같은 SHA256이면 원장 설정을 바꾸지 않으며, 다른 값이면 활성 복구 코드 한 개를 원자적으로 교체한다. 기존 SQLite 원장·암호화 키·소유자의 예산·비용·불확실한 요청·기기 세션을 보존한다. 환경 변수가 없어도 원장에 설치한 코드는 유지한다. 회전하려면 새 코드의 SHA256으로 변수를 변경한 뒤 배포한다. 코드 교체는 기존 코드의 새 연결만 차단한다. 이미 발급한 기기 세션은 기존 세션 해제 절차를 사용한다.

재사용 코드는 만료·사용 횟수 제한 없이 연결에 다시 사용할 수 있다. 연결마다 기존 규칙의 기기별 access/refresh token을 새로 발급한다. 코드를 Bearer로 사용하지 않으며 비용 승인·일/월/건별 상한·결과 조회·멱등성 계약을 바꾸지 않는다. IP별 연결 시도 제한은 실패에도 유지하고, 재사용 코드로 만드는 세션도 소유자 전체 분당20회로 제한한다. 기존 10분 일회용 코드와 refresh 회전/재사용 탐지/해제는 그대로 동작한다.

연결·복구 자체는 모델을 호출하지 않는다. 자동 테스트의 모의 호출과 실제 공급자 호출을 구분한다. `/health`의 `features.reusable_connection=1`은 기능 배포 확인이며 실제 소유자 코드 연결은 별도로 검증한다.
